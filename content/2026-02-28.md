## i3

A few years ago I ran Manjaro w/ i3 as my daily driver. After the initial learning curve, the sheer speed a tiling window manager provides is second to none.

One of my favorite features was the [scratchpad](https://i3wm.org/docs/userguide.html#_scratchpad).  Scratchpad allowed you to maintain the tiling nature of the workspace but still have a toggleable overlay(s) available.

I most frequently used this to create a scratchpad terminal (I used `urxvt` at the time because of font support and speed).

```bash
# move the currently focused window to the scratchpad
bindsym $mod+Shift+minus move scratchpad

# Show the next scratchpad window or hide the focused scratchpad window.
# If there are multiple scratchpad windows, this command cycles through them.
bindsym $mod+minus scratchpad show
```

## macOS window management sucks

macOS Tahoe window pinning sucks. period. It sucks even more in a multi monitor setup when trying to find the magic two pixels in order to pin a window when the edge is between two monitors.

If I had a choice I would either work off my Framework 13 running Bluefin or my [Debian dev server](https://pcpartpicker.com/list/GcW93y).

Needless to say, the window management situation in macOS leads me to have a bunch of overlapping 3/4 screen windows and using `CTRL`+`↑` and `CTRL`+`↓` to switch around. I'm not even going to go into the monstrosity that is Stage Manager.

> Honestly I probably should dive into a tiling manager like [Rectangle](https://rectangleapp.com/) or [AeroSpace](https://github.com/nikitabobko/AeroSpace), but for now I'll suffer. While writing this article I found out about [holding `Option`](https://support.apple.com/guide/mac-help/tile-app-windows-mchlef287e5d/mac) to avoid needing to snap via edge proximity, which could be a game changer.

## Ghostty

Enter [Ghostty](https://ghostty.org/), "a fast, feature-rich, and cross-platform terminal emulator".

Ghostty feels snappier and lighter than iTerm2, so I've been using it for pretty much all command line work (aside from some `ssh` sessions that cannot handle Ghostty's terminal profile).

While exploring its configuration options one day I came across the [quick terminal](https://ghostty.org/docs/config/reference#quick-terminal-position) feature.

I quickly realized it had the potential to completely fix my window management.

For the most part, my work is spent switching between the terminal and another application.

Sometimes its VSCode with it's built-in terminal,

```text
quick-terminal-position = center
quick-terminal-animation-duration = 0
keybind = global:super+`=toggle_quick_terminal
quick-terminal-size = 70%,70%
```

## The result

combine w/ tmux and neovim to provide:

- tab 1: todo list
- tab 2: work log
- tab 3: k9s
- tab 4+: general terminal work

## Limitations

- resizing when monitor / screen layout changes
- could fix by setting https://ghostty.org/docs/config/reference#quick-terminal-screen to `macos-menu-bar`
- press 3x on fresh ghostty boot
